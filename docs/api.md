# API 명세

> 이 파일이 원본이다(D-40). 마지막 반영일: 2026-11-06

## 공통 규칙

- 별도 백엔드와 REST API는 없다(D-18). 읽기는 `src/lib/content.ts`의 서버 함수, 쓰기는 Server Action이 맡는다.
- Server Action은 `POST`로 호출한 페이지 주소에 보낸다(Next.js가 처리). 읽기 함수는 HTTP 요청이 아니다.
- 읽기 함수는 서버에서만 실행한다. anon 키로 읽고 RLS가 공개된 행만 돌려준다. 결과는 `"use cache"`로 캐시한다.
- Server Action은 누구나 POST로 부를 수 있는 공개 입구로 본다. 화면에서 검사했더라도 입력은 서버에서 다시 검증한다.
- Server Action의 결과는 예외를 던지지 않고 값으로 돌려준다: 성공 `{ ok: true }`, 실패 `{ ok: false, reason, fieldErrors? }`. 화면은 `reason`에 따라 안내 문구를 고른다.
- 코드 안 이름은 `camelCase`, DB 칸 이름은 `snake_case`다. 변환은 `lib/` 한 곳에서만 한다. 폼 필드 이름은 외부 규칙(Turnstile의 `cf-turnstile-response`)을 따를 수 있다.
- 서버 전용 키(service_role)는 서버 코드에서만 쓴다. 브라우저 코드에 내려가면 안 된다(D-13).
- 관리 Action은 시작 시 `src/app/admin/_lib/auth.ts`의 `requireAdmin()`으로 Auth 서버의 사용자와 `is_admin()` 결과를 확인한다. 허용된 사용자 세션의 클라이언트로 저장해 RLS가 한 번 더 확인한다. 조회 실패도 거부하며 권한 결과는 요청 간 캐시하지 않는다. 저장 뒤 관련 화면 캐시를 새로 고친다.
- 로그인·로그아웃은 `/admin`의 Server Action에서 Supabase Auth를 호출하고 `@supabase/ssr`로 세션 쿠키를 관리한다. 성공하면 `/admin`으로 이동하고, 실패하면 `{ ok: false, reason }`을 반환한다. 회원가입 화면은 없다(D-42). 방문·클릭 지표는 PostHog로 보내며 함수를 만들지 않는다(D-36).

## 관리자 인증과 운영 설정 (#43, D-42)

- 주소는 언어와 무관한 `/admin`이다. 별도 최상위 레이아웃의 Metadata와 Proxy 응답 헤더로 검색 노출을 제외한다.
- Proxy는 `/admin/:path*`에서 `getClaims()`로 세션을 검증·갱신하고 새 쿠키를 요청과 응답에 전달한다. 응답은 `private, no-store`로 두며 관리자 표 조회는 페이지·Action에서 한다.
- 레이아웃은 단독 권한 경계가 아니다. 페이지는 `<Suspense>` 안에서 `requireAdmin()`을 호출하고, 향후 각 관리 Action도 데이터 접근 전에 같은 확인을 한다. 비로그인은 로그인 폼, 비관리자는 접근 거부, 관리자만 관리 화면을 본다.
- 세션 쿠키는 `HttpOnly`, `SameSite=Lax`, `Path=/`로 두며 배포 환경에서는 `Secure`를 적용한다. 관리자 인증은 서버에서만 처리하고 service_role을 쓰지 않는다.
- 필요한 환경 변수는 기존 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`다. 로컬 `.env.local`과 Vercel의 해당 환경에 설정한다. 추가 환경 변수는 없다.
- 관리자 계정 1개는 대시보드에서 만들고 그 Auth `user_id`를 `admins`에 등록한다. 다른 role이나 이메일 목록으로 관리자를 판정하지 않는다.
- **추후 직접 할 설정(이번 PR에서 보류):** Supabase 프로젝트 → **Authentication → Sign In / Providers → User Signups → Allow new users to sign up 끄기 → Save changes**. `Allow anonymous sign-ins`도 끈 상태를 유지한다. 이메일·비밀번호 로그인을 위해 Email 제공자는 켜 둔다.
- 설치된 SDK의 `node_modules/@supabase/supabase-js/src/SupabaseClient.ts`는 전달된 공개 키를 Auth의 `apikey` 헤더로 넘기고, `node_modules/@supabase/auth-js/src/GoTrueClient.ts`의 `signUp()`은 `/auth/v1/signup`으로 POST한다. 회원가입 UI가 없어도 공개 anon 키를 사용하는 클라이언트는 `auth.signUp()`을 직접 요청할 수 있다. 가입 허용 설정이 켜져 있으면 일반 Auth 계정이 생성될 수 있다. 현재는 상용 서비스가 아니므로 신규 가입 차단은 보류하고 담당자가 추후 위 설정을 직접 적용한다(2026-11-06 사용자 결정). `admins` 등록과는 별개여서 가입만으로 관리자 권한을 얻지는 못한다.
- 2026-11-06 구현 중 대시보드를 읽기 전용으로 확인한 시점에는 신규 가입 허용 켜짐, 익명 로그인 꺼짐, Email 제공자 켜짐이었다. 설정 변경과 실제 가입 요청은 수행하지 않았다.
