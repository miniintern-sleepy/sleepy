# API 명세

> 원본: [노션 설계 문서](https://app.notion.com/p/e1289238025e82eba21901dc55b67002) · 마지막 반영일: 2026-10-31 (v1)
> 바뀌면 노션을 먼저 고치고 이 파일에 옮긴다(D-31).

## 공통 규칙

- 별도 백엔드와 REST API는 없다(D-18). 읽기는 `src/lib/content.ts`의 서버 함수, 쓰기는 Server Action이 맡는다.
- Server Action은 `POST`로 호출한 페이지 주소에 보낸다(Next.js가 처리). 읽기 함수는 HTTP 요청이 아니다.
- 읽기 함수는 서버에서만 실행한다. anon 키로 읽고 RLS가 공개된 행만 돌려준다. 결과는 `"use cache"`로 캐시한다.
- Server Action은 누구나 POST로 부를 수 있는 공개 입구로 본다. 화면에서 검사했더라도 입력은 서버에서 다시 검증한다.
- Server Action의 결과는 예외를 던지지 않고 값으로 돌려준다: 성공 `{ ok: true }`, 실패 `{ ok: false, reason, fieldErrors? }`. 화면은 `reason`에 따라 안내 문구를 고른다.
- 코드 안 이름은 `camelCase`, DB 칸 이름은 `snake_case`다. 변환은 `lib/` 한 곳에서만 한다. 폼 필드 이름은 외부 규칙(Turnstile의 `cf-turnstile-response`)을 따를 수 있다.
- 서버 전용 키(service_role)는 서버 코드에서만 쓴다. 브라우저 코드에 내려가면 안 된다(D-13).
- 관리 Action은 로그인했고 `admins`에 있는 사용자만 호출한다. 코드에서 확인하고 RLS가 한 번 더 확인한다. 저장 뒤 관련 화면 캐시를 새로 고친다.
- 로그인·로그아웃은 Supabase Auth 기능을 그대로 쓴다. 방문·클릭 지표는 PostHog로 보내며 함수를 만들지 않는다(D-36).
